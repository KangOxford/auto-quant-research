What Is Auto Quant Research?

Auto Quant Research is a two-layer system for finance microstructure replication. The labor that does not need human judgement is fully automated and runs while the user sleeps. The decisions that do need human judgement are surfaced as a small, structured set of choices, never a wall of raw output. We call these the Execution Layer and the Decision Layer; together they make up the Human-in-the-Loop contract.

🌙 Execution Layer — Auto Research in Sleep

Human-out-of-the-loop. The agent parses the paper PDF, dispatches nine parallel subagents to design the data pipeline, world model, and empirical regression spec, generates approximately one thousand lines of code, commits to Git for full traceability, submits a SLURM batch job, monitors the job to completion, and pushes raw results to Notion. All of this happens autonomously while the user is offline.

Bound by: data correctness, infrastructure plumbing, code generation. Not by judgement.

🤝 Decision Layer — Human in the Loop

Surfaces only the choices that change the direction or goal of the replication: which paper claims to test in depth, which ticker subsets matter, which robustness checks to add, which counter-narrative to highlight. The user reviews the auto-generated draft on Notion and edits or approves what they care most about proving.

Bound by: scientific judgement, narrative framing, what the user wants to claim.

End-to-End Flow

LAYER 1  ·  NOTION  (Wiki + Annotation)
(a) PUSH

Raw Results → Notion

The Execution Layer auto-publishes every answer (regression tables, plots, reproduction code) to a fresh Notion page tied to the paper.

(b) ANNOTATE

Decision Layer review

The user marks up the Notion page directly: highlight, underline, or inline [brackets] to flag what matters, what to drop, what to expand.

(c) WIKI

Knowledge base for humans

New knowledge gets compiled into Wiki sub-pages, cross-referenced by concept and paper, so the next person reading the Notion page understands the full context.

↓
LAYER 2  ·  OVERLEAF  (Final Paper Draft)
(d) SETTLE

Annotations → Overleaf draft (reference for human rewrite)

A downstream pass reads the user's annotations on Notion (highlights, underlines, brackets) and lifts the marked content into an Overleaf LaTeX draft. The draft is not the published paper — it is a structured reference that the human author uses to rewrite the paper line by line, sentence by sentence, in their own voice. Each section in the draft is tagged to the exact Notion revision and Git commit that produced it, so the human always has full traceability back through the Wiki to the underlying replication while writing.

Wiki = Notion + One Sub-page per Answer

The Wiki referenced in step (c) above lives on Notion, not on this static site. Notion was chosen because it offers (i) free-form rich pages with KaTeX equations and inline images, (ii) sub-page hierarchy that maps cleanly onto a knowledge graph, and (iii) public REST API for programmatic write access. The Wiki is structured one-concept-per-page with cross-links between pages, following the LLM-Wiki paradigm proposed by Andrej Karpathy in April 2026.

Mechanism: every time the Decision Layer signs off on a specific answer (a robustness check, a stylized-fact estimate, a counterfactual rollout result), that answer is auto-pushed as a new sub-page under the parent Wiki page on Notion. The sub-page captures the question, the evidence, and the references back to the Notion revision and the Git commit that produced it. Over time, the Wiki accumulates one sub-page per substantive answer, cross-linked into a growing knowledge graph.

Why a Wiki, and not a chat log: the Wiki is a comprehension scaffold, not a storage trick

Every replicated paper introduces new domain knowledge: a stylized fact, a regression specification, a counterfactual scenario, a market microstructure assumption. None of this knowledge enters the user's head automatically. If the user is going to make good decisions in the Decision Layer, deciding which angle to back, which robustness check to insist on, which result to push to Overleaf, the user has to actually understand what the Execution Layer found.

That is what the Wiki is for. The Wiki turns each replication's findings into a structured page that a human can read and learn from, with cross-links to the related concepts that make the finding interpretable. It is a reading surface, not just a storage surface. A chat log is a record of what was said; a Wiki is a record of what was understood.

This is the heart of the Human-in-the-Loop contract. If the human cannot understand the result, the human cannot decide on the result. Without comprehension there is no real signoff, just rubber-stamping. The Decision Layer's authority depends on the user actually grasping what the agent did, why it did it that way, and what the result implies. The Wiki is the artifact that makes that possible at scale, paper after paper, across an accumulating body of new knowledge.

Downstream consumption

Because the Wiki is plain markdown under the hood, it can be exported and fed into other tools without re-derivation. A practical example: export a set of sub-pages and upload to NotebookLM to generate a 10–20 minute "Audio Overview" podcast for offline listening, or to query the Wiki in source-grounded chat. The Wiki produces the asset; downstream tools consume it.

Internal hooks: each Edit/Write to a registered Wiki markdown file triggers a PostToolUse Claude Code hook that archives the previous Notion revision and writes the new revision. Zero LLM tokens are consumed per sync — the hook is a shell script that calls the Notion REST API directly.

The data layer is real Nasdaq order flow at nanosecond resolution; the simulation layer is built on JAX and Mamba3.

Examples

Auto Quant Research has been validated on multiple finance microstructure papers. Each example pins a specific Git commit so that reproductions anchor to an exact code state, not a moving branch. The simulator that powers all four examples is described separately in The Engine Behind below.

COMPLETED The flagship live demonstration: a full replication of Dugast, Marta, Riva (2026) “Market Depth and Execution Delays” using Nasdaq LOB data.

Paper finding: β(log depth → log delay) = 0.133 to 0.169 on NYSE TAQ data (2000s).

Our replication: β = +0.2140 (SE 0.0106, t = 20.26), N = 46,094,530 limit orders, 8 Nasdaq primaries × Q1 2025. SLURM job 4093982, 1 node × 64 CPU, wall-clock 12 minutes.

The result is directionally consistent with the paper but somewhat larger, expected because Nasdaq primaries in 2025 have faster matching engines and more extreme depth heterogeneity than the NYSE sample, and venue fragmentation plus the PFOF ecosystem shift the depth-delay relationship upward. Per-ticker heterogeneity ranges from β = +0.289 (GOOG, strong depth-delay link) to β = -0.073 (MSFT, venue fragmentation effect).

COMPLETED A canonical microstructure stylized fact: trade-sign series exhibit long memory, with Hurst exponent H ≈ 0.7 across liquid stocks and venues.

Paper finding: H = 0.696 ± 0.032 on LSE 1999–2002, across 20+ stocks (Lillo & Farmer 2004, Studies in Nonlinear Dynamics & Econometrics).

Our replication: DFA H = 0.7053 on full-year GOOG 2022 LOBSTER data (251 trading days, 10,868,894 trade-sign events). Within ±1σ of the paper value. SLURM job 4384364, 1 node × 64 CPU, wall-clock 8 minutes.

The classical estimator is implemented in scripts/hurst_lillo_farmer.py: extract LOBSTER ·7z archives, filter event_type ∈ {4, 5} for executed trades, take the ±1 trade-direction series, and compute the Hurst exponent via both ACF tail-decay and Detrended Fluctuation Analysis. DFA is more robust on finite samples and is the canonical estimator used by the paper.

REPLICATION PENDING The square-root impact law: meta-order permanent price impact scales as I ∝ Q0.5, exponent δ ≈ 0.5 universally across stocks, futures, and asset classes (Tóth et al. 2011, Phys. Rev. X).

Paper finding: I(Q) = Y · σdaily · √(Q/Vdaily), where Y ≈ 0.5 is a universal constant. Reflects market self-organized criticality with V-shaped latent order book.

Replication plan: same .7z extraction pipeline, then heuristic meta-order clustering (same-side trades within 60-second gap) followed by log-log OLS on (I, Q). Expected exponent in [0.4, 0.6] across 8 tickers × 4 years. Spec at papers/toth_2011_sqrt_impact.md.

REPLICATION PENDING Models the LOB at each price level as an independent birth-death queue: limit-order arrivals decay as power law λ(i) = k/iα, cancellations strictly proportional to queue size θ(i) · n, market orders Poisson with rate μ.

Paper finding (Sky Perfect Communications, TSE Level II): α = 0.52, μ = 0.94/min, θ(1) = 0.71, all in units of limit-order-size blocks per minute.

Replication plan: extract LOBSTER message events, split by event_type into limit / cancel / market, fit three rates per level. Expected α ∈ [0.5, 2.5] (cross-market variation), μ ≈ 1/min, θ(1) ∈ [0.4, 0.8]. Spec at papers/cont_stoikov_talreja_2009.md.

The World Model

Every replication runs on top of the same World Model: a learned synthetic-market environment, calibrated against real Nasdaq order flow, that lets us synthesize counterfactual depth shocks, replay metaorders, and stress-test stylized facts beyond what any single dataset can probe. The World Model is what turns Auto Quant Research from a regression-running script into a genuine experimental laboratory.

The World Model used here comes from the sigma0 project. We deliberately treat the specific architecture (currently a token-level autoregressive state-space model) as an implementation detail: the World Model is the abstraction that matters, the architecture is one substitutable choice. Future Auto Quant Research releases may swap in different sigma0 World Models without changing the replication interface.

⚙ WORLD MODEL

How the World Model Powers Verification

The World Model is a generative simulator of LOB order flow. Given the preceding order stream, it produces a probability distribution over the next event (limit order, cancellation, market order, quote update) at nanosecond resolution, calibrated on real Nasdaq data. Because every field, both categorical (event type, direction) and quantized numerical (price, size, time delta), is modeled as a discrete categorical with cross-entropy loss, the World Model is a true general density model: no Gaussian shortcut, no parametric distribution assumption. Counterfactual scenarios are generated by conditional rollout, not by hand-crafted Monte Carlo.

Verification mechanism: each replicated paper is verified inside a synthetic environment generated by the World Model. Synthetic depth shocks, metaorder injections, and counterfactual rollouts produce delay and price-impact distributions that can be measured the same way as on real data. If the World Model captures the stylized fact, the empirical claim from the paper transports to a controlled environment where the user can probe its boundary conditions, beyond what any single dataset can probe.

Current implementation (subject to change in future releases): a state-space architecture from the sigma0 project, trained autoregressively on tokenized order messages across multiple tickers and trading years.

Reproducibility: the current World Model checkpoint is published as a GitHub Release — 567 MB tar.zst, sha256-pinned. See model card for download, decompression, and load instructions. The architecture origin is documented in the sigma0 project page.

Automation Pipeline

After a paper is ingested, the Execution Layer dispatches a fan-out of N parallel subagents (the count is task-dependent: simple regression replications use a handful; structural model identification uses more). Each subagent owns one slice of the design or implementation work, the data pipeline, the World Model interface, the empirical regression spec, the figure code, and so on. The orchestrator merges their outputs, commits the result to Git for full traceability, and sbatches the analysis to the HPC cluster.

Open Questions

AutoResearch currently extracts a regression spec from the abstract, methods, and results sections. Should it also parse appendices, supplementary tables, robustness checks, and footnotes? More extraction means more faithful replication but larger context windows for the orchestrator. The optimal trade-off is open.

When our replication produces a coefficient that is directionally consistent with the paper but quantitatively different, the gap could reflect either a real change in the market regime since the paper was written, or a bug in our feature construction. The agent currently does not have a principled way to distinguish replication noise from real market evolution.
